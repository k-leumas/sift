<objective>
Close review warning WR-02: a rules.yaml whose text holds NUL or another control character passes `sift config check` (oneLine only rejects CR and LF; from, domain and phrase entries check nothing of the kind), and then every decision insert for that mailbox fails, because the rule set snapshot is jsonb and PostgreSQL jsonb cannot hold NUL (SQLSTATE 22P05).

This plan was split out of 03-16 (which keeps WR-01, the model-reason check) so each plan stays within its context budget. It touches only the rules schema and its tests, so it runs in wave 1 with no dependency.

The fix is "reject, never repair" (D-05: a rules problem is found by config check and named with its YAML path): the strict schema rejects control characters with a positioned message; nothing is stripped.

Purpose: a rules file the worker could not store is refused before any pass runs, so one bad file never makes a mailbox fail on every pass (CLS-06), and the versioned rule set stays storable (CLS-01).
Output: control-character checks in packages/core/src/rules/schema.ts, an end-to-end config-check test and schema cases.
</objective>
