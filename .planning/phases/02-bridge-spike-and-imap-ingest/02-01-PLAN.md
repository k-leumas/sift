<objective>
Ship Proton Bridge as a Compose service built from source at a pinned release (D-29, D-30, D-32, D-37, D-38):
- a two-stage Dockerfile
- an entrypoint that unlocks the GPG/pass keychain and refuses to start otherwise
- socat that exposes Bridge's loopback-only IMAP port on the container IP
- a logged certificate fingerprint, which is what owners pin in config.yaml (D-73)

Wire the Compose contract: the long-running `bridge` service mounts only the vault volume, and a separate one-shot `bridge-init` service (profile `tools`) alone mounts `.env.mailboxes` and the config directory, run as `docker compose run --rm bridge-init` (D-39, D-72, D-79). Keep compose-smoke isolated from both.

Purpose: every later Bridge step (init, the live spike, the worker connection) runs on this image. Proving image build, keychain fail-closed and STARTTLS through the published port first catches a dead end before any login work.

Output: `bridge/Dockerfile`, `bridge/entrypoint.sh`, `scripts/bridge-smoke.sh`, the `bridge` Compose service and volume, compose-smoke changes and their tests.
</objective>

bridge/entrypoint.sh modes (argument 1, default serve):
  serve         unlock keychain (fail closed, exit 78), start socat on <container IP>:1143 -> 127.0.0.1:1143 and bridge --noninteractive,
                both as uid 1000 and both in the background (a shell function cannot be exec'd), forward TERM/INT to both, `wait -n`,
                then stop the survivor and exit non-zero naming which child exited first; log the presented certificate's SPKI fingerprint in the background
  keychain-init idempotent: create the GPG key + pass store + canary when absent, then unlock and verify; prints "Bridge keychain ready"
  (02-08 adds: init, configure, cli, repair)
Exit codes: 0 ok, 64 unknown mode, 78 keychain/vault refusal (fixed messages, never the passphrase).
Process model: the entrypoint runs as root under tini; every gpg/pass/socat/bridge process runs as uid 1000 (user `bridge`) via `setpriv --reuid=1000 --regid=1000 --init-groups`. Root is kept only so 02-08's init can write the bind-mounted .env.mailboxes in place with its host owner and mode intact.
Container paths: /data (sift-bridge volume: HOME, GNUPGHOME=/data/.gnupg, PASSWORD_STORE_DIR=/data/.password-store, XDG_CONFIG_HOME=/data/config, XDG_DATA_HOME=/data/data, XDG_CACHE_HOME=/data/cache), /run/user/1000 (gpg-agent socket dir).
Only in the bridge-init service (D-79, D-81): /run/sift/.env.mailboxes (mailbox env file, read-write), /run/sift/config (config dir, read-only) and /run/sift/.env.mailboxes.bak (the host's pre-created backup file, read-write). In the bridge service none of these paths exists.
SPKI fingerprint format (shared with apps/worker/src/imap/pin.ts in 02-04 and the config value imap.tls.pin_sha256 in 02-02): base64 of sha256 over the DER SubjectPublicKeyInfo, i.e. `openssl x509 -pubkey -noout | openssl pkey -pubin -outform DER | openssl dgst -sha256 -binary | openssl base64 -A` (44 characters ending in `=`).

   - `keychain_init` is idempotent. It writes `$GNUPGHOME/gpg-agent.conf` with `allow-preset-passphrase`, `max-cache-ttl 34560000` and `default-cache-ttl 34560000`. When no secret key exists it runs `gpg --batch --pinentry-mode loopback --passphrase-fd 0 --quick-gen-key sift-bridge-vault rsa3072 encr never`, feeding the passphrase on stdin (never as an argument). Then `pass init <fingerprint>`, then `pass insert -m sift/canary` with a fixed non-secret marker text.

     - If no secret key exists, print `Bridge is not initialised: run docker compose run --rm bridge-init` and exit 78.
     - Start the agent with `gpg-connect-agent /bye`. Preset the passphrase for every keygrip from `gpg --list-secret-keys --with-keygrip --with-colons` using `$(gpgconf --list-dirs libexecdir)/gpg-preset-passphrase --preset`, with the passphrase on stdin.
     - Require `pass show sift/canary` to succeed, else print `Bridge keychain locked: check SIFT_BRIDGE_KEYCHAIN_PASSPHRASE` and exit 78.
     - Refuse an insecure vault: if `/data/config/protonmail/bridge-v3/insecure` exists, print `Insecure Bridge vault found; Sift refuses to run it. Remove the sift-bridge volume and run docker compose run --rm bridge-init again` and exit 78.

   - `spki_fingerprint` reads a PEM on stdin and prints the fingerprint in the interfaces format.
   - `print_fingerprint`: wait up to 60 s for 127.0.0.1:1143, capture the certificate with `openssl s_client -starttls imap -connect 127.0.0.1:1143 </dev/null | openssl x509 -outform PEM`, then print `Bridge certificate SHA-256 (public key): <fingerprint>` (the value owners pin, D-73). Write no file.
   - Mode `serve`:
     - require_passphrase, then keychain_unlock.

Do not try to `exec` as_bridge: bash cannot exec a shell function, and an exec'd Bridge would leave socat unsupervised (addresses review concern Cursor MEDIUM, L383@45a500e).
     - Trap TERM and INT: send TERM to both PIDs, wait for them, exit 0.
     - `wait -n` on the two PIDs. Whichever exits first, print `socat exited; stopping Bridge` or `Bridge exited; stopping socat` to stderr, TERM the other, wait for it, and exit 1, so the restart policy recreates both.
