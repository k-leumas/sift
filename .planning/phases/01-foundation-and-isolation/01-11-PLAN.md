<objective>
Harden worker startup (D-34, D-55) and prove that mailbox secrets never land anywhere persistent (FND-02, success criterion 2):
- the drift refusal tells the owner to rerun setup;
- startup DB retries are classified;
- the worker refuses a privileged role;
- a sentinel-password test scans config files, every database column and all process output.

Purpose: Docker restarts the worker without re-running setup (Pitfall 11), so the worker itself must notice a stale registry and an unreachable or misconfigured database. The sentinel test is the automated half of success criterion 2; the human half runs on the target machine (plan 01-12).

Output: `apps/worker/src/runtime/startup.ts`, `@sift/db/connect`, the updated worker command, three tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker restart -> worker | Worker restarts without setup re-running (Pitfall 11) |
| SIFT_DATABASE_URL (owner-supplied) -> worker session | A wrong URL could point at a privileged role |
| worker memory (secrets) -> persistence (DB, logs) | Secrets must not cross |
