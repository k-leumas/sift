<objective>
Close the review warnings that share CR-01's root cause or make its throw path reachable: WR-01 (a model reason with NUL or another control character cannot be stored, so the message fails on every pass and five in a row make the pass throw) and WR-02 (a rules file with control characters passes sift config check but fails every decision insert).

Both are "reject at the boundary, never repair": the model's answer and the owner's rules file are validated in code; nothing is stripped or fixed except the database backstop for Ollama-supplied trace fields.

Purpose: no input, hostile or accidental, can make a message or a mailbox fail on every pass with a database error (CLS-06); injected text cannot use control characters to break the write path (SEC-01).
Output: a code-level reason check, a NUL backstop in recordDecision, strict rules-schema checks, and an end-to-end test file.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output -> decision | the model's reason (steerable by injected email text) is validated before it reaches decide() and jsonb |
| Ollama response -> trace | thinking, raw, done_reason and response_model strings from Ollama are stored in decision.spans |
| owner rules file -> trusted prompt and rule_set | rules.yaml text reaches the system prompt and rule_set.snapshot jsonb |
