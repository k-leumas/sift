<objective>
Stand up local Postgres 18 + pgvector with the superuser-only bootstrap (roles sift_owner and sift_backup, database sift, extension vector), and the env/gitignore layout that keeps secrets out of git. This is the database every DB-backed test and the full Compose stack build on (FND-01). It also creates the role split that makes forced RLS meaningful (ISO-02, D-36/D-39/D-66).

Purpose: bootstrap is the only step that needs a superuser. One idempotent `.sql` file serves Compose initdb, CI and the test harness (research Pattern 3). After init, the superuser is never used by setup or the worker (D-39).

Output: `db/bootstrap.sql`, `compose.yaml` with the `db` service only (plan 01-12 adds `setup` and `worker`), `.env.example`, `.env.development.example`, `.gitignore` updates.
</objective>

  <action>
1. `db/bootstrap.sql` runs as the image superuser through psql with ON_ERROR_STOP. It is idempotent and has no shell wrapper:
   - `\getenv owner_pw SIFT_DB_OWNER_PASSWORD` and `\getenv backup_pw SIFT_DB_BACKUP_PASSWORD`.
   - Create role sift_owner if it is missing, with `SELECT format(... %L ...) WHERE NOT EXISTS (...) \gexec`: `LOGIN CREATEROLE NOSUPERUSER NOBYPASSRLS NOCREATEDB`. CREATEROLE lets `sift migrate` create and alter sift_app; under PG16+ rules it can only alter roles it created.
   - Create role sift_backup if it is missing: `LOGIN BYPASSRLS NOSUPERUSER NOCREATEDB NOCREATEROLE` (D-66).
   - Then always run `ALTER ROLE ... PASSWORD %L` for both roles through `format()` + `\gexec`, so a rerun rotates passwords to the env values. `%L` quoting is mandatory: a password is never concatenated into SQL.
   - `GRANT pg_read_all_data TO sift_backup`.
   - `\connect template1`, then `CREATE EXTENSION IF NOT EXISTS vector`. Every later CREATE DATABASE, including sift_test_*, inherits it (Pitfall 2: pgvector is untrusted, so sift_owner cannot create it).
   - `\connect postgres`, then create database sift `OWNER sift_owner` if it is missing (`\gexec`).
   - `\connect sift`, then `CREATE EXTENSION IF NOT EXISTS vector`.
   - Do NOT create the application role here: a role the superuser creates cannot be altered by sift_owner (research Pattern 3). `sift migrate` creates it as sift_owner (plan 01-03).
2. `compose.yaml`, db service only. Use no top-level `name:` and no healthcheck `start_interval`; the dev machine runs Compose v2.2.3.
   - `image: pgvector/pgvector:0.8.7-pg18-trixie` (D-17).
   - `environment` from interpolation with required markers: `POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set in .env}`, and the same for `SIFT_DB_OWNER_PASSWORD` and `SIFT_DB_BACKUP_PASSWORD`.
   - `volumes`: `sift-pgdata:/var/lib/postgresql` (PG18 image path, Pitfall 3) and `./db/bootstrap.sql:/docker-entrypoint-initdb.d/10-sift-bootstrap.sql:ro`.
   - TCP healthcheck: `pg_isready -h 127.0.0.1 -U postgres -d sift`, interval 5s, timeout 3s, retries 20, start_period 10s. TCP so the temporary init server never reads as healthy (Pitfall 7).
   - `ports: ["127.0.0.1:${SIFT_DB_PORT:-5432}:5432"]`, loopback only.
   - `restart: unless-stopped`.
   - Top-level `volumes: { sift-pgdata: { name: sift-pgdata } }` (D-25).
3. `.env.example`: the five variables from the interfaces block, with empty values (SIFT_DB_PORT=5432). Add comments: generate each password with `openssl rand -hex 24`, because URL-safe values keep connection URLs valid. This file never holds mailbox passwords; those go in `.env.mailboxes`, added in plan 01-12.
4. Local run: if `.env` is missing, create it from `.env.example` with fresh `openssl rand -hex 24` values. `.env` is ignored; Task 2 adds the remaining ignore rules. Then run `docker compose up -d --wait db`.
