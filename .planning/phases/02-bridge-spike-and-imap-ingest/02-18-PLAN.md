<objective>
Make the worker's IMAP connection real and fail-closed for both kinds of server, under the owner's TLS rule "never send credentials or data over an unverified connection" (D-80):
- STARTTLS (default) or implicit TLS, never plaintext (D-42, D-74)
- for Bridge, a public-key pin from config (D-73): the presented certificate is captured on a handshake that carries nothing else, compared with the pin, and then trusted as the only CA of a second, login connection that also re-checks the pin (D-40, D-80)
- for public-CA servers, normal chain and hostname verification

Purpose: these rules are the security boundary of every later IMAP call (02-09, 02-11, 02-13, 02-16), and the capture is what `sift bridge trust` shows the owner (02-15). The capture handshake is the one place verification is off; D-80 records that decision, and this plan proves on the wire that the exception carries nothing.

Output: `apps/worker/src/imap/{capture,connect}.ts`, a recording fake IMAP server with test certificates, and the capture and connect tests. Split from the original 02-04, which keeps the test server, the pin function and the dependency install.
</objective>

capture.ts (this plan; the ONLY file under apps/worker/src that turns certificate verification off, and only for this handshake, per D-80):
  export interface CapturedCertificate { pem: string; spkiSha256: string; validTo: string; subject: string }
  export async function capturePeerCertificate(opts: { host: string; port: number; mode: 'starttls' | 'implicit'; timeoutMs?: number }): Promise<CapturedCertificate>;
    // starttls: plain TCP, read the greeting.
    //   - Greeting carries a capability code without STARTTLS: reject with an Error of code SIFT_NO_STARTTLS, having written nothing.
    //   - Otherwise write exactly one line, `<tag> STARTTLS`. A tagged NO or BAD rejects with SIFT_NO_STARTTLS.
    //   - On the tagged OK, upgrade with tls.connect({ socket, servername (hostnames only) }) with verification off, read getPeerCertificate(true).raw, destroy the socket.
    //   - Nothing else is ever written: no CAPABILITY, no ID, no LOGOUT, no login command, no credential.
    // implicit: tls.connect directly with verification off; read the certificate on 'secureConnect', destroy the socket; nothing is written.
    // Every call is a fresh handshake. Nothing is cached in module state and nothing is written to disk (D-80).

  options: host, port, secure, doSTARTTLS, auth {user, pass}, logger (false disables pino output), tls (merged into tls.connect, for the implicit connection and the STARTTLS upgrade),

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker -> IMAP server (Bridge) over the Compose network | Credentials and mail cross this TCP link |
| capture handshake | A deliberately unverified TLS session that must carry nothing beyond STARTTLS and the handshake (D-80) |
| capture connection -> login connection | The certificate seen on the first connection must be the one the second connection presents |
