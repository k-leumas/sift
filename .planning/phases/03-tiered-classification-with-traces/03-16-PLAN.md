<objective>
Close review warning WR-01, which shares CR-01's root cause and makes CR-03's throw path reachable: a model reason with NUL or another control character cannot be stored, so the message fails on every pass and five in a row make the pass throw.

The fix is "reject at the boundary, never repair": the model's answer is validated in code; nothing is stripped or fixed except the database backstop for Ollama-supplied trace fields.

WR-02 (a rules file with control characters passes sift config check but fails every decision insert) has the same "reject, never repair" shape but touches only the rules schema; it is plan 03-21 (wave 1), split out of this plan to keep each plan within its context budget.

Purpose: no input, hostile or accidental, can make a message fail on every pass with a database error (CLS-06); injected text cannot use control characters to break the write path (SEC-01).
Output: a code-level reason check, a NUL backstop in recordDecision, and an end-to-end test file.
</objective>
