<objective>
Extend the mailbox-scoped schema for ingest:
- message identity (D-12) and stored metadata (D-08), with no body column (D-06)
- a separate message_location table (D-15)
- a body-cache table (D-06, D-07)
- folder_sync watermarks and generations (D-18, D-23..D-25)
- the new mailbox_status states (D-26, D-34)

Each table-adding generated migration is paired with a custom one (FORCE RLS, grants, triggers), as in Phase 1, and a custom preflight migration runs first. This project applies schema changes only through these committed migrations, run by its own `migrate()` (`sift migrate`, and the test template in globalSetup); it never uses `drizzle-kit push`. The schema-gate's push step is therefore the existing migrate path, exercised by this plan's migrate, catalog and isolation tests against a real database.

Purpose: idempotency is a database guarantee (UNIQUE constraints), not luck in application code. Every later ingest plan writes through these tables, and the catalog and isolation suites must keep passing.

Output: schema, migrations 0005 (preflight), 0006 (generated) and 0007 (custom) with snapshots, Scope registration, and updated seed and tests.
</objective>
