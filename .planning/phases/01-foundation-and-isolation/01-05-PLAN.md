  <action>
Extend `collectCatalogViolations` with the following checks, each producing named entries.

1. Per-table privileges for sift_app:
   - Use `has_table_privilege` for SELECT, INSERT, DELETE, TRUNCATE, REFERENCES and TRIGGER, and `has_any_column_privilege` for UPDATE (catches column-level grants).
   - Normal scoped tables (non-allowlisted, not in APPEND_ONLY_TABLE_NAMES): SELECT, INSERT, UPDATE, DELETE true.
   - Append-only tables: SELECT and INSERT true, UPDATE and DELETE false.
   - public.mailbox: SELECT true, all others false.
   - drizzle.__drizzle_migrations: all false.
   - Every table: TRUNCATE, REFERENCES and TRIGGER false.
2. Roles:
   - sift_app: rolsuper, rolbypassrls, rolcreaterole and rolcreatedb all false.
   - sift_app owns nothing: no pg_class or pg_proc rows owned by `'sift_app'::regrole`.
   - `has_schema_privilege('sift_app','public','CREATE')` is false, and `has_schema_privilege('sift_app','drizzle','USAGE')` is false.
   - `pg_has_role('sift_app','sift_owner','MEMBER')` is false.
   - sift_owner: rolsuper and rolbypassrls false (FORCE must bind the owner, D-41).
   - D-66: `select rolname from pg_roles where rolbypassrls and not rolsuper` equals exactly ['sift_backup']. sift_backup owns nothing and has no INSERT, UPDATE, DELETE or TRUNCATE on any user table.
3. Registry: the ordered column list of public.mailbox from pg_attribute (attnum > 0, not dropped) equals MAILBOX_COLUMNS (D-06).
4. Recommended additions:
   - Every non-allowlisted table except mailbox_status has a UNIQUE constraint on exactly (mailbox_id, id).
   - mailbox_status's primary key is exactly (mailbox_id) (D-07).
   - Every FK whose conrelid and confrelid are both non-allowlisted tables includes the mailbox_id attnum in conkey and in confkey (D-04).
   - Every table with an `updated_at` column has a non-internal BEFORE UPDATE row trigger whose function is `set_updated_at`.
5. Negative tests, each on its own fresh DB as sift_owner or admin. Each expects a violation naming the object:
   - `GRANT TRUNCATE ON message TO sift_app`.
   - A second permissive policy `CREATE POLICY widen ON message FOR SELECT TO sift_app USING (true)`. This is the ISO-02 ordering edge: OR-ed permissive policies would widen access, so exactly one is enforced.
   - As admin, `CREATE ROLE rogue_bypass BYPASSRLS`, dropped afterwards in a finally block.
   - `GRANT UPDATE (updated_at) ON decision TO sift_app` (column-level update on an append-only table).
  </action>
