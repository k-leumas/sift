## Key Learnings

- [2026-10-06] `docker compose logs <svc>` of a container that was started again (not recreated) still shows the earlier runs' lines; use `--timestamps` or `--since` before blaming the current run (02-19: a stale setup "not writable" line).
- [2026-10-06] During Bridge's initial sync INBOX uidNext grows ~400/min and new UIDs carry OLD INTERNALDATEs; the worker stores them as historical rows (no body, not eligible). uidNext growth is useless as a new-mail signal mid-sync; use `sift bridge probe <slug> --scan-limit 0 --sample 200` and count newest-sample internalDate >= send time.
- [2026-10-06] To start the worker without touching Bridge: `docker compose up -d --build worker` (recreates setup + worker only).

- [2026-10-06] Proton Bridge v3.27.0 (gluon): no CONDSTORE/QRESYNC, ENABLE and STATUS HIGHESTMODSEQ answer BAD; UID COPY from an EXAMINEd mailbox is refused ("the mailbox is read-only") - SELECT the source for COPY. COPYUID is returned (UIDPLUS). X-Pm-Internal-Id is on every message and byte-stable across folders.
- [2026-10-06] Bridge's initial sync assigns UIDs newest-first (high UID = OLD mail) and takes well over 30 min for a large account; new mail arriving mid-sync gets the next free UID. IDLE EXISTS during sync is from synced old mail, so the probe's idle.newUid is not a new-mail signal until sync settles.
- [2026-10-06] Probe sample = newest N by sequence; while Bridge syncs it slides, so restart comparisons need a fixed UID range. Ad-hoc read-only scripts can be mounted into the worker image (`-v script.ts:/app/apps/worker/x.ts:ro --entrypoint node worker /app/apps/worker/x.ts`) and reuse loadConfig + openImap (pinned).
- [2026-10-06] `vitest run --root /` scans the whole filesystem and hangs; never use it for a scratch test.
- `pnpm -s lint` exits 2 under pnpm 12 even when `pnpm lint` exits 0 — check gate exit codes without -s.
- Linux uid/permission bugs hidden by Docker Desktop (macOS) can be reproduced in a throwaway `docker run --rm --user root sift:local` by chown-ing paths to 1001 and `su node` (uid 1000).
- Biome diagnostics do not show in --stdin-file-path mode; to probe an override, copy biome.json into a scratch dir with a .gitignore + git init and lint a probe file there.
