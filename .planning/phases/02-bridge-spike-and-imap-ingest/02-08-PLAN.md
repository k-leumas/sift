<objective>
Implement the one-time Bridge setup as `docker compose run --rm bridge-init`, the one-shot service that alone mounts .env.mailboxes, its backup and config (D-72, D-79, D-81):
- the owner logs in through Bridge's own CLI (password and 2FA without echo, D-36)
- a small Go helper inside the Bridge image uses Bridge's gRPC frontend to switch off telemetry and automatic updates
- the helper reads the IMAP password and writes it straight into `.env.mailboxes` under each matching mailbox's `password_env` (D-39)
- init prints the certificate fingerprint the owner pastes into `imap.tls.pin_sha256` (D-73)

Add a non-interactive `repair` mode for the live spike.

Purpose: the IMAP password never passes through the owner's terminal, the vault never phones home, and the worker gets exactly the env line it needs. Only the bridge and bridge-init containers touch the vault, and only bridge-init sees .env.mailboxes and config (D-79).

Output: the Go helper with tests that run inside the image build, and the entrypoint's init/configure/cli/repair modes, with the Bridge smoke extended to cover configure.
</objective>
