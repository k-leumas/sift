<objective>
Give the worker and the CLI the database operations classification needs, inside the scoped API: the pending and re-run candidate queries (which the generic helpers cannot express), the single decision write path with the body-expiry update, rule-set and prompt-version upserts by hash, the latest-decision read and the body restore used after a refetch.

Purpose: apps reach the database only through @sift/db (ISO-04); every decision goes through one function that validates the trace, so no code path can write a malformed or inconsistent decision.
Output: classify.ts and prompt-version.ts use-cases, a classification API on Scope, exports and real-database tests.
</objective>
