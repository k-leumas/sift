<objective>
Close the core of verification gap 1 (review CR-01, roadmap SC5, CLS-06): tell a failure confined to one message from an Ollama outage, so one message that makes Ollama return HTTP 500 (or time out) every time no longer blocks every older LLM-bound message and no longer keeps its mailbox, ingest included, in backoff.

Today draftFor turns every chat infra result into a pass-wide llmBlocked. Pending mail is scanned newest first, so such a message is the first LLM-bound one reached on every later pass; the pass returns infra, runBatch throws ClassifyInfraError and the supervisor backs off up to 15 minutes.

After this plan: on a chat server_error or timeout the pass re-runs the mail-free preflight. If Ollama answers it, only that message is skipped for this pass and the pass continues (at most OLLAMA_MESSAGE_FAILURES_PER_PASS per pass; one more is treated as an outage). If the preflight fails, it is an outage exactly as before. No decision is ever written for a skipped message in this plan (D-16's "an outage is never a decision" holds); 03-18 makes repeated failures visible and stops them costing Ollama time, and 03-19/03-20 offer the owner a terminal review state.

The test that codified the old behaviour ('a 500 on the third call stops LLM work for the pass', classify-run.test.ts) is replaced deliberately, keeping its outage assertions in a re-probe-confirmed variant.

Purpose: one bad message never stops the others (CLS-06, SC5).
Output: run.ts re-probe and per-pass budget, rewritten and new tests at pass, batch and leak level, AI-SPEC and CONTEXT notes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored email -> Ollama | a hostile or merely huge email can make Ollama's runner crash or time out on that one prompt |
| Ollama failure -> pass control and mailbox status | the pass decides whether a failure is the message's or the server's, which drives backoff and the owner-visible state |
| pass -> logs | the skip is logged; Ollama's error text can quote the prompt |
