  <behavior>
    - computeBackoff(1, 60000, () => 0.5) === 120000; computeBackoff(20, 60000, () => 1) === 900000 (cap); random 0 gives 0.8x and random 1 gives 1.2x below the cap
    - start(): runBatch is called once per enabled mailbox on the first tick; never for an entry with disabledAt
    - No overlap: mailbox A's runBatch never resolves; after 5 poll intervals of fake time, runBatch(A) was called exactly once while B (fast) was called on each due tick; a debug log records each skipped A run
    - Independent failure: A throws -> onBatchError(A, err) called, B still runs on schedule; A's next attempt happens no earlier than computeBackoff(1, ...) after the failure; after a later success A returns to the plain poll interval
    - Disable transition: the registry returns A with disabledAt on the next tick -> onMailboxStopped(A) is called exactly once and runBatch(A) is never called again; A re-enabled -> runs again
    - New mailbox C appearing in the registry starts on the next tick
    - readRegistry throws -> error logged, heartbeat NOT called for that tick, ticking continues
    - stop(): after stop no further runBatch calls; resolves { drained: true } when in-flight batches finish before the timeout and { drained: false } when one exceeds it
  </behavior>
  <action>
1. `backoff.ts`: per the interfaces block (D-51 cap 15 min).
2. `supervisor.ts`: keep per-mailbox state `{ inProgress, failures, nextRunAt, known }`.
   - On each tick, after readRegistry:
     - Entries absent or disabled that were known: drop their state and call `onMailboxStopped` once for disabled ones (D-45).
     - Enabled entries: create state if new.
     - Due entries (`now() >= nextRunAt`): run when idle; when in progress, log debug `skipped: previous run still in progress` and leave nextRunAt unchanged (D-50).
   - A run's success sets `failures = 0` and `nextRunAt = now() + pollIntervalMs`.
   - A run's failure increments failures, sets `nextRunAt = now() + computeBackoff(failures, pollIntervalMs, random)` and awaits `onBatchError`. An error thrown by `onBatchError` itself is logged and swallowed, so one mailbox never takes down the supervisor.
   - `stop` sets a stopped flag, clears the timer, and races `Promise.allSettled(inFlight)` against the timeout.
3. `supervisor.test.ts`: vitest fake timers (`vi.useFakeTimers()`) plus injected `now`, `random` and stub deps, implementing every behavior bullet.
