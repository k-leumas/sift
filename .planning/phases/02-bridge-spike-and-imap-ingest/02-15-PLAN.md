<objective>
Give the owner the command D-73 describes: `sift bridge trust <slug>` connects the way the worker does, shows the fingerprint the worker sees and compares it with the pin in config.yaml. The owner then compares it with what `docker compose run --rm bridge-init` printed and pastes it. Nothing is trusted automatically.

Keep the pinned Bridge release from going stale (D-31): a Renovate config that bumps the tag and commit together, and a CI job that builds and smoke-tests every bump.

Purpose: the worker fails closed when Bridge's certificate changes (02-13). This command is the owner's way to see what changed. Proton stops serving outdated Bridge versions, so the pin must move, and every move must still build and serve STARTTLS.

Output: `bridge-trust.ts`, its CLI registration and tests, `renovate.json`, `.github/workflows/bridge-image.yml`, and the extended static test.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-SC | Tampering | Renovate-proposed Bridge bumps | medium | mitigate | Tag plus commit bumped together; the Dockerfile's commit check fails a mismatched bump; CI builds and smoke-tests each PR; the owner merges |
| T-02-50 | Spoofing | Blindly accepting an attacker's certificate | high | mitigate | The command never writes trust; the owner compares two independent readings (init output inside the Bridge container, and what the worker sees) before editing config (D-73) |
