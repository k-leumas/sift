<objective>
Give the owner the one-way choice that closes the last part of verification gap 1 ("a terminal state for a message that keeps failing ... either a review decision with a new reason, which needs a REVIEW_REASONS / CHECK / D-16 amendment, or the message id surfaced in last_error"), and, if the owner picks the review decision, land its trace and database contract.

03-17 and 03-18 already deliver the reversible terminal state: after three passes in which Ollama failed on a message alone (each confirmed by a healthy re-probe, the last by a mail-free canary chat), the worker stops sending it and names it in mailbox_status. The message then stays pending: it is never labelled and never held for review, so the phase goal ("every ingested message gets a category ... or is marked for review") and the core value ("auto-labelled correctly or explicitly held for the owner") are not met for it.

option-review makes that message a review decision with a new reason, llm_error. That amends locked decision D-16 ("an outage is never a decision" stays true; a failure confined to one message for three passes becomes a review) and D-31's reason list, and it changes a database CHECK and the trace contract that Phase 4 apply, the TRC-05 trace CLI and M2 read. Stored llm_error rows are append-only, so this cannot be undone without a data migration: a one-way door, hence the blocking human checkpoint first.

option-keep leaves that residual gap open on purpose, so it must be on record where re-verification reads it: the owner's acceptance becomes an `overrides:` entry in the 03-VERIFICATION.md frontmatter (the mechanism that file names for CR-01, human verification item 3), quoted again in the SUMMARY.

This checkpoint is also where the owner sees the D-16 clarification 03-17 made without a checkpoint (03-17-SUMMARY.md, section Locked decision changes).

Purpose: the owner, not the planner, decides whether D-16 is amended, and either answer leaves no unrecorded gap.
Output: the recorded decision; with option-review, the core and database contract for llm_error (03-20 then makes the worker write it); with option-keep, the owner override in 03-VERIFICATION.md.
</objective>
