<objective>
Add the cross-process ingest lock that keeps the CLI backfill and the worker from ever ingesting the same mailbox at once (D-03). It runs each mailbox's chunk transactions on the lock's own connection, so concurrent mailboxes cannot exhaust the pool (Pitfall 9). Also add the status use-cases for the new mailbox states: connecting during startup grace (D-34), and needs_attention with the held count for the volume valve (D-26).

Purpose: the worker integration (02-13) and the CLI backfill (02-16) both need exactly this primitive. The status functions give the owner-visible state D-26/D-33/D-34 promise.

Output: `packages/db/src/lock.ts`, a scope.ts refactor, status.ts additions, exports and real-database tests.
</objective>

  lock.ts:
    export const INGEST_LOCK_CLASS = 815309;   // two-int advisory key space, separate from the bigint keys above
    export interface IngestSession { readonly mailboxId: string; run<T>(fn: (scope: Scope) => Promise<T>, options?: WithMailboxOptions): Promise<T> }
    export type IngestLockResult<T> = { acquired: true; value: T } | { acquired: false };
    export async function withIngestLock<T>(db: AppDb, mailboxId: string, fn: (session: IngestSession) => Promise<T>): Promise<IngestLockResult<T>>;
      // InvalidMailboxIdError before any query; `select pg_try_advisory_lock($1::int, hashtext($2))`;
      // finally: `select pg_advisory_unlock($1::int, hashtext($2))` then release the client (release(error) when the client errored).
  status.ts:
    export async function recordConnecting(scope: Scope, at?: Date): Promise<void>;     // state 'connecting', last_error null, last_seen_at
    export async function recordNeedsAttention(scope: Scope, held: number, slug: string, at?: Date): Promise<void>;

    export async function recordBackfillProgress(scope: Scope, progress: { done: number; total: number; finished: boolean }): Promise<void>;
