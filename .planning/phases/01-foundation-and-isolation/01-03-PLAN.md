<objective>
Create the mailbox-scoped schema for every M1 table, the migrations that enforce isolation in the database (ISO-01, ISO-02), the `migrate()` function that applies them as sift_owner, and the Vitest harness that runs those real migrations against a throwaway database (D-47).

Purpose: isolation must exist before any mail-derived data does. Forced RLS, grants and the updated_at trigger cannot be expressed in drizzle-kit 0.31, so they live in custom migrations committed next to each generated one. The 0.45 migrator applies all pending migrations in one transaction, so no table ever exists without FORCE.

Output: Drizzle schema + RLS policy factory, five committed migrations, `@sift/db/migrate` `migrate()`, root `vitest.config.ts`, the DB test harness and seed helpers, and a migrate smoke test.

Schema push note (schema-gate contribution): D-19 forbids `drizzle-kit push`. Here the "apply schema to a live database before verification" step is the real `migrate()` run in Vitest globalSetup against Postgres 18, which every DB test in this phase depends on. That is the [BLOCKING] equivalent: types passing without a live migration cannot produce a green run.
</objective>
