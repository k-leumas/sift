<objective>
Close verification gap 2 (review CR-02): a body that Sift writes back for a message that already has a decision must get its 7-day expiry when it is written, not only when a later decision happens.

Today restoreBody (sift classify refetch) and storeMessages (ingest re-insert of a known message) write the body with expires_at null and rely on a decision in the same run to start the clock. When that decision never comes (Ollama outage, Ctrl-C, a failure inside the message), the body of an already-decided message is kept forever: deleteExpired only removes rows whose expires_at has passed, deleteOrphanBodies keeps bodies of decided messages, and the worker never revisits decided mail. That breaks the README's "A body is deleted 7 days after the message's decision", D-32 and the closed status of T-03-20.

Purpose: private mail text the owner was told is short-lived is never kept indefinitely.
Output: one shared rule in packages/db ("a body written for a decided message expires 7 days after the write"), applied by restoreBody and storeMessages, with an end-to-end refetch-then-outage test and the T-03-20 record updated.
</objective>
