<objective>
Close the visibility half of verification gap 1 and review WR-03, and give a message that keeps failing a terminal state that needs no schema change (03-VERIFICATION gap 1, missing item 2: "per-runtime failure count, then ... the message id surfaced in last_error").

After 03-17 a message Ollama fails on alone is skipped for the pass, but it is retried on every pass (costing a call, up to 120 s on CPU, each time) and nothing tells the owner: status shows plain ok. Messages that throw or have no body are likewise only in a warn log line (WR-03).

After this plan: the pass reports the ids it could not classify; the batch stores them as a non-error notice in mailbox_status (state stays ok) and `sift mailbox list` shows it; a message Ollama failed on alone in MESSAGE_FAILURE_PASSES passes is no longer sent to Ollama by this worker process. 03-22 (split out of this plan for the context budget) then makes `sift classify` name such a message by id and explains the notice in the README; 03-19 asks the owner whether such a message should instead end as a review decision (llm_error).

Purpose: no message is silently left unclassified, and a repeat failure stops consuming the owner's hardware.
Output: run.ts notice and failure memory, status/list rendering, tests.
</objective>
